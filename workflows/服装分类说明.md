# 服装分类说明

## 为什么要重做分类

v1.9.8 之前，568 套服装挤在 **14 个分组**里，而且分组又偏又常错：

| 问题 | 具体情况 |
|---|---|
| 一组独大 | 「服装库·性感暴露」**160 套**，占全部的三成 |
| 分组不准 | 导入库自带的分组（`d_dress` / `d_casual`）按内容看经常是错的 —— 例如 `d_dress` 里的「黑色颈带·大腿带」实际是 garter straps + thigh strap，`d_casual` 里的「丰满透明」实际是 bustier + see-through |
| 配件混进来 | 「肘部手套·黑色手套」「眼镜·项链」这种**配件拼盘**也当成整套服装分类 |

挑衣服的人关心的是「这是件什么衣服」，不是「当初从哪个库导入的」。
所以 v1.9.9 改成**按服装内容自动分类**。

## 分类是怎么算出来的

规则在 `py/outfit_groups.py`。做法是**计分匹配**，几条关键经验都是踩坑换来的：

1. **只看前 3 个标签做主判定**
   导入数据里第一个标签就是主项（`眼镜·项链` → `glasses, necklace, ...`）。
   如果让配件也参与计分，「白色连裤袜·高跟鞋」会被算成"日常休闲"。

2. **计分而不是先命中先赢**
   关键词越长越具体分越高，这样 `bikini` 能压过 `skirt`。

3. **词边界匹配**
   `bra` 不能命中 `braid` / `bracelet`，`suit` 不能命中 `swimsuit`。
   （这两个都真的误判过：「辫子」进了内衣、「夏季薄款校服」进了职业。）

4. **配件拼盘单独一组**
   整套里只有手套/袜子/首饰、没有任何主服装
   （dress/skirt/uniform/kimono/bikini/armor…）→ 归「🧤配件组合」。

5. **露出类的权重降半**
   `bare shoulders` / `cleavage` 这类是**附带标签**，不降权的话会把主服装盖过，
   导致「露出系」一组吞掉 119 套。

6. **游戏 COS 不参与关键词匹配**，按原分组直接归位。

## 分组显示顺序

分组顺序 = `RULE_GROUPS` 里的定义顺序，**按"具体 → 宽泛"排**：
先是护士/女仆/警察这些有明确职业暗示的，再是题材类（和服/中华/奇幻/科幻），
最后是露肩/露脐这类属性类，以及 上衣/外套/裤装/连衣裙 这类版型类。

## 自己加分组

改 `py/outfit_groups.py` 里的 `RULE_GROUPS`：

```python
("oc_yourgroup", "你的分组名", "🎨", 1.0, (
    "english tag", "中文关键词")),
```

* 第 4 个参数是**权重倍率**（1.0 正常，露出类那种附带属性用 0.6）
* 关键词含中文就按子串匹配（权重 +2），纯英文按词边界匹配（权重 = 长度）
* 加完重启 ComfyUI 就生效（分类是运行时算的，不用改数据文件）

## 验证

```bash
# 离线：分组数、分布是否均衡、有没有空组
python tools/animansfw_verify_zip.py

# 真浏览器：分组按钮 + 组内随机
node tools/animansfw_browser_outfit.mjs
```

`animansfw_verify_zip.py` 里有一条断言专门防退化：
**最大的组不能超过 15%**（否则又会变成"一组占三成"那种等于没分类的状态）。

## 分类不完美的地方

关键词分类做不到 100% 准，抽查时还看到这类情况：

* 「心形合唱·黑色Langerie大腿高」→ 泳装（`swimsuit` 命中了，但这套其实是内衣配件）
* 「白色连裤袜·高跟鞋」→ 军装/海军（`sailor` 相关标签的误伤）

这类是原始标签本身就有歧义（一套预设里混了好几种东西），
要彻底准得给 568 套逐条人工标注。当前的做法是：**大方向不出错**
（想看校服能点到校服、想看内衣能点到内衣），个别的归组偏差可以接受。
如果你发现某套明显归错了，告诉我具体是哪套，我调关键词。
