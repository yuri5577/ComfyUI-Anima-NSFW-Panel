# 游戏 COS 服装说明

v1.9.6 新增。碧蓝航线 / 封印者 / 通用 cos 共 **50 套**，分成 9 个组。

---

## 一个重要的诚实说明：标签是怎么定的

**我没有凭记忆编服装标签。** 所有用到的标签都查过 Danbooru 的真实热度
（`tools/animansfw_research2.py`，走本地代理查 `/tags.json`，只保留
post_count 达标的写法）。查证过程中发现三件必须记下来的事：

### 1. `rigging` 才是舰装的正字

`ship_rigging` 不存在或极少见，**`rigging` 有 33757 帖**。用错了模型不认识。

### 2. 碧蓝航线的「阵营制服」并不是一个标签

各阵营在 Danbooru 上的标签是**徽章**写法：

| 阵营 | Danbooru 实际标签 | 帖子数 |
|---|---|---|
| 皇家 | `royal_navy_emblem_(azur_lane)` | 394 |
| 白鹰 | `eagle_union_(emblem)` | 552 |
| 铁血 | `iron_blood_(emblem)` | 653 |
| 重樱 | `sakura_empire_(emblem)` | 715 |
| 北方联合 | `northern_parliament_(emblem)` | 147 |
| 撒丁帝国 | `sardegna_empire_(emblem)` | 150 |
| 鸢尾 | `iris_libre_(emblem)` | 114 |
| 维希 | `vichya_dominion_(emblem)` | 131 |

**没有** "royal navy uniform" 这种标签。所以阵营感是**拼**出来的：

```
通用海军/军装标签（naval uniform / military uniform / epaulettes / peaked cap）
  + 徽章 + 舰装（rigging）+ 阵营配色
```

比如皇家：`naval uniform, military uniform, epaulettes, peaked cap, necktie,
white gloves, pleated skirt, black thighhighs, boots, capelet` —— 白+金+蓝的
皇家海军配色，而不是一个不存在的专有标签。

### 3. 单个角色的皮肤标签太长，Anima 不一定见过

碧蓝航线每个角色的皮肤在 Danbooru 上是
`character_(皮肤名)_(azur_lane)` 这种超长标签（例如
`bismarck_(beacon_of_the_iron_blood)_(azur_lane)`，只有 135 帖）。
用它们出图会很不稳，所以**不用**，改用「基础服装 + 阵营元素」的组合。

封印者那边情况类似：`closers` 主标签有 3518 帖，角色标签
（`seulbi_lee` 294、`levia_(closers)` 290）也有，但**没有成套的服装标签**，
所以封印者的服装也是按「黑衣小队制服 / 次元猎人战斗服 / 各队制服」这类
描述性组合来搭，风格参考游戏设定。

## 随机服装

服装视图顶部有一行：

```
🎲 随机一套服装   ☐ ＋配饰（同色系，1~2 个）   可抽 568 套
```

### 「搭配合理」是怎么保证的

用户明确要求搭配合理 —— 不能随机撒标签，那会出「水手服 + 盔甲 + 泳装」。
分两层：

**第一层：整套预设随机（主力）**
568 套预设每一套**本身就是成套的**，随机抽一套天然合理。
抽的范围跟着你当前的筛选走（来源 / 分组 / 搜索词），
所以「先点 👑碧蓝·皇家 再随机」只会在那 5 套里抽。
还会避免连续抽到同一套。

**第二层：配饰补全（可选，默认关）**
勾上「＋配饰」会再补 1~2 个配饰。配饰从**固定白名单**
（31 条，都是我人工过一遍能百搭的）里抽，并满足三条约束：

| 约束 | 目的 | 实现 |
|---|---|---|
| 同槽位最多 1 个 | 别出现两顶帽子 | 槽位表：头 / 颈 / 手 / 腿 / 脚 / 腰 / 脸 |
| 不是已有配饰的颜色变体 | 已有 `black thighhighs` 就不再加 `thighhighs` | 反向子串匹配 |
| 颜色跟整套同色系 | 别粉发带配黑军装 | 从预设标签里提取色系，给配饰上同色前缀 |

> ⚠️ 槽位判断**不能用子串**。踩过两个坑：
> * 预设已有 `black belt`（腰），字符串里也有 "belt"，于是把
>   `garter belt`（腿）也拦了 —— 但这俩是**不同的东西**，可以同时戴（77 次误判）
> * 预设已有 `white gloves`（手），却还是加了
>   `black fingerless gloves`（手）—— 真漏判
>
> 用槽位表两个都能判对。`tools/animansfw_random_test.mjs` 跑 4000 次统计违规，
> 现在四项都是 0。

### 实测

| 项目 | 结果 |
|---|---|
| 随机 30 次 | 抽到 29~30 套不同 |
| 单次耗时 | 中位 ~6ms，最大 ~10ms |
| 分组内随机 25 次 | 100% 落在该组（`组=al_royal`） |
| ＋配饰 20 次 | 20 次都补上，共 27~35 个，无违规 |
| 切 9 个分组 | 中位 63ms / 最大 78ms |
| 面板 DOM | 273 节点 |

## 顺手修掉的一个搜索 bug

服装搜索原本只匹配 `中文名 + 英文名 + 标签`，**不匹配分组名**。

结果：游戏 COS 的预设名是「皇家·海军制服」、标签里也没有「碧蓝」，
用户搜「碧蓝」**一个都搜不到**（实测 0 张）。现在把分组名也并进搜索范围，
搜「碧蓝」能命中全部 32 套碧蓝航线服装（皇家 + 白鹰 + 铁血 + 重樱 + 其它阵营 +
舰娘基础），搜「封印者」命中 10 套。

## 自己测

```bash
# 随机约束（离线，跑 4000 次统计违规）
node tools/animansfw_random_test.mjs

# 真浏览器（需要先启动 ComfyUI）
node tools/animansfw_browser_outfit.mjs
```

`random_test` 会检查：同槽位不重复、无重复标签、不与预设同类冲突、
配饰同色系、每个预设都能配上配饰、游戏 COS 已入库、
以及**游戏 COS 用到的标签都在标签库里**（否则互斥组认不出它们）。
