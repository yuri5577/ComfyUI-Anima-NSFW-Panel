# 缩略图本地缓存

## 问题：为什么要挂 VPN

面板里的预览图**全部来自境外 CDN**：

| 资源 | 数量 | 来源 |
|---|---|---|
| 服装预设预览 | 430 | `cdn.jsdelivr.net` |
| 姿势参考预览 | 297 | `cdn.jsdelivr.net` |
| 角色立绘 | 8017 | `blobs.animadex.net` |

每张图都是**独立的境外请求**，所以：

* 首屏一两百张 = 一两百次跨境握手，很慢
* jsDelivr 的 `gh` 路径在国内常被 DNS 污染 / 按 IP 限速，时好时坏
* 完全没网时整面板都是「无图」

> 实测：这几个域名**直连是通的**（DNS 正常、能下），所以问题不是"完全不通"，
> 而是"逐张请求太多、容易被污染"。这决定了缓存方案可行 —— 只要成功加载过一次，
> 之后就永远走本地。

## 做法：后端代理 + 磁盘缓存

前端不再直连 CDN，改成请求**本地 ComfyUI**：

```
浏览器 → 127.0.0.1:8188/anima_nsfw/thumb?u=<原始URL>
                ↓
         后端：命中磁盘缓存？ → 直接吐文件（毫秒级）
                ↓ 未命中
               下载 → 校验是图片 → 落盘 → 吐给前端
```

浏览器只跟 `127.0.0.1` 说话，所以**不挂 VPN 也能看**，离线也能看。

## 怎么用

### 自动（按需）

正常浏览就会自动缓存：翻到哪张下哪张，下过一次之后就一直走本地。
头部「🖼 缩略图 开」保持开启即可。

### 手动（一次弄好）

头部有个 **「⬇ 缓存缩略图」** 按钮：

| 操作 | 效果 |
|---|---|
| 点一下 | 弹确认后开始批量下载；选「取消」则**只缓存服装+姿势**（更省空间） |
| Shift + 点 | **清空**缓存（会显示占用了多少 MB） |
| 鼠标悬停 | 显示缓存目录、文件数、占用大小、命中/下载/失败次数 |

按钮上的数字会实时更新（如 `⬇ 已缓存 218 张 4.4MB`）。

**规模参考**：服装 430 + 姿势 297 = **727 张，约 15 MB，1~2 分钟**；
角色立绘 6413 张可见，约 **250 MB**，十分钟左右 —— 所以角色默认要你确认。

## 缓存位置

```
<ComfyUI>/user/anima_nsfw_thumb_cache/<哈希前两位>/<可读文件名>.<哈希>.<扩展名>
```

例如：

```
user/anima_nsfw_thumb_cache/af/ganyu_(genshin_impact),_genshin_impact.af5dd65108d0.webp
user/anima_nsfw_thumb_cache/d0/1741118591102.d00eecf104d1.webp
```

* **两级目录**（哈希前两位）避免单目录塞几万个文件
* 文件名**保留原名**便于人工翻找，后缀哈希保证不同 URL 不互相覆盖
* 可用环境变量 `ANIMANSFW_THUMB_CACHE` 指定别的位置

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/anima_nsfw/thumb?u=<URL>&force=1` | 取图（必要时下载）。响应头 `X-Anima-Cache: hit/stored/miss` |
| GET | `/anima_nsfw/thumb_cache/stats` | 缓存统计（文件数/占用/命中/下载/失败/重试） |
| POST | `/anima_nsfw/thumb_cache/warm` | 批量预热，body `{"urls":[...], "force":false}` |
| POST | `/anima_nsfw/thumb_cache/clear` | 清空，body `{"confirm":true}` |

## 安全（重要）

这个接口能替客户端发 HTTP 请求，所以**必须**限制：

| 限制 | 说明 |
|---|---|
| **域名白名单** | 只有 jsDelivr（含 fastly/gcore/testingcf 镜像）和 `blobs.animadex.net` 能代理。否则就是个开放代理（SSRF）—— 实测 `https://cdn.jsdelivr.net.evil.com/x.png` 这种子域欺骗也会被拒 |
| 只允许 http/https | `file://` 一律拒 |
| **magic bytes 校验** | 落盘前确认真的是图片。CDN 出错时会返回 HTML 错误页，直接存下来会让前端一直破图 |
| 单文件上限 12 MB | 防止把磁盘塞满 |
| 失败不缓存 | 下次刷新还有机会补上 |

## 性能（实测数据）

| 做法 | 小图（8~10 KB）耗时 |
|---|---|
| 每次新建连接（urllib） | 600~900 ms/张 |
| **keep-alive 连接复用** | **185~240 ms/张** |
| 串行首张（冷启动建 TLS） | 偶尔 80 秒 + 超时失败 |

于是加了：

1. **连接复用**（`http.client` keep-alive）—— 小图的 TCP + TLS 握手成本比传数据还大
2. **分类超时** —— 建连 8 秒、读 30 秒，连不上就快速失败而不是耗满读超时
3. **失败重试** 2 次（退避 0.4s / 1.2s）—— 实测连接类故障重试立刻成功；404 不重试
4. **8 线程并发批量预热** —— 预热 727 张约 1~2 分钟

> ⚠️ **踩过的坑：连接池必须每线程独立**。
> `http.client.HTTPConnection` **不是线程安全的**。第一版用"全局按域名缓存一条连接"，
> 8 并发时 150 张里挂了 **129 张**，错误全是
> `CannotSendRequest: Request-sent` / `ResponseNotReady: Idle`
> —— 多个线程抢同一条连接，状态机错乱。**串行时完全正常**，所以只看串行测不出来。
> 现在用 `threading.local()`，每线程各持一组连接。
>
> 第二个坑：`warm()` 第一版写成 `for x in _EXECUTOR.map(f, todo)` ——
> `Executor.map` 是**阻塞迭代**的，而且在调用方线程里等结果。
> 调用方（aiohttp 路由）本身是 `run_in_executor` 起的一个线程，
> 于是整个 warm 变成**串行**下载，"8 并发"完全是假的。
> 现在用 `submit` + `as_completed`。

```bash
# 真浏览器：所有缩略图走本地代理、能解码、二次命中、缓存按钮、批量预热

```

## 如果你还是打不开图

1. 先确认 **ComfyUI 在跑**（缓存接口在 ComfyUI 进程里）
2. 头部「🖼 缩略图」开关是不是关着
3. 点一下「⬇ 缓存缩略图」看有没有报错；悬停看失败次数
4. 代理需要走 VPN 的网络环境：设环境变量
   `ANIMANSFW_THUMB_PROXY=http://127.0.0.1:7897` 再重启 ComfyUI
   （默认**故意不读**系统代理变量 —— 缓存的意义就是一次下好后本地读）
5. 缓存目录不可写：`user/anima_nsfw_thumb_cache` 需要写权限，
   或用 `ANIMANSFW_THUMB_CACHE` 指到别处

## 边界

* 缓存的是**第三方 CDN 上的缩略图**（AnimaTags-DB / Dressing-doll 项目），
  只是下载到你本机；仓库里**不含任何图片**
* 仓库体积没变（不打包图片），缓存是运行时生成的
